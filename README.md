# ESP32-S3 ETH: ETHERNET → WI-FI → ESP-NOW

Существующий проект ESP-IDF **5.4.4**, одна прошивка для двух плат.
Без Arduino и отдельных demo-проектов.

## Структура

```text
espnow_test/
├── CMakeLists.txt
├── sdkconfig
├── main/
│   ├── CMakeLists.txt
│   └── app_main.c
├── components/
│   ├── display/             существующий ST7789 на SPI3
│   ├── link_common/         link_config.h и link_packet.h
│   ├── wifi_link/           STA, reconnect, UDP через Wi-Fi
│   ├── ethernet_link/       W5500, Ethernet netif, UDP через Ethernet
│   │   ├── CMakeLists.txt
│   │   ├── ethernet_link.c
│   │   └── include/ethernet_link.h
│   ├── espnow_link/         резервный ESP-NOW unicast
│   └── transport/           ACK, приоритеты, счётчики, обновление TFT
├── docs/espnow_test.previous.c.txt
└── README.md
```

Существующие пустые каталоги `components/espnow` и `components/ethernet`
сохранены. Предыдущий main находится в docs как текстовый reference,
не участвует в сборке. Активный main только инициализирует display и запускает
transport. Ethernet запускается после wifi_link_init, который уже создал
общую инфраструктуру esp_netif и event loop.

## Плата и GPIO

Используется встроенный W5500 Waveshare ESP32-S3-ETH:
SPI2, MOSI 11, MISO 12, SCLK 13, CS 14, INT 10, RST 9, SPI 20 MHz.
Пины сверены с [документацией Waveshare](https://docs.waveshare.com/ESP32-S3-ETH/Development-Environment-Setup-ESP-IDF).
API драйвера взят из установленного ESP-IDF 5.4.4; примеры производителя,
рассчитанные на другую версию IDF, не копировались как проект.

TFT остаётся на SPI3 с прежними пинами, инициализацией, цветами и framebuffer.
Для надписи ETHERNET в существующий шрифт добавлена буква H.
В sdkconfig включён CONFIG_ETH_SPI_ETHERNET_W5500.

## Локальная конфигурация перед сборкой

После клонирования репозитория создайте локальный конфиг из примера:

```sh
cp components/link_common/include/link_config.example.h components/link_common/include/link_config.h
```

В `link_config.h` укажите свой SSID, пароль и сетевые настройки. Рабочий
`link_config.h` исключён из Git через `.gitignore`. В репозитории хранится только
`link_config.example.h` с заглушками `YOUR_WIFI_SSID` и `YOUR_WIFI_PASSWORD`.
Готовые бинарники и содержимое `build/` не публикуются: они могут содержать
Wi-Fi пароль, встроенный компилятором. Сборка выполняется локально.

## Сеть

Ethernet обеих плат подключается к роутеру/свитчу общей сети.
Все настройки находятся в `components/link_common/include/link_config.h`.

| Интерфейс | Плата A | Плата B |
| --- | --- | --- |
| Wi-Fi | 192.168.0.100 | 192.168.0.101 |
| Ethernet | 192.168.0.110 | 192.168.0.111 |

Маска 255.255.255.0, gateway 192.168.0.1, UDP-порт 3333 на обоих интерфейсах.
Адреса интерфейсов разные, чтобы не получить конфликт IP при одновременной работе.
Адреса .110/.111 должны быть свободны и зарезервированы/исключены из DHCP pool.
Если сеть другая, измените ETH и Wi-Fi адреса, маски и gateway в конфигурации.

Wi-Fi SSID/пароль сохранены в одном месте и не выводятся в лог.
A/B определяется по **STA MAC**, независимо от Ethernet:
A = 3C:0F:02:D7:86:74, B = 3C:0F:02:D8:15:70.
Ethernet получает отдельный уникальный MAC через esp_read_mac(ESP_MAC_ETH).

DHCP включается отдельно для каждого интерфейса:
LINK_USE_STATIC_IP = 0 для Wi-Fi, LINK_ETH_USE_STATIC_IP = 0 для Ethernet.
Нужны DHCP reservations и соответствующие LINK_*_DHCP_PEER_FOR_* значения
для противоположной платы. Автоматический поиск peer не реализован.
LINK_ETH_ENABLED = 0 позволяет отключить Ethernet и оставить два беспроводных транспорта.

## Привязка UDP к интерфейсам

Оба UDP-сокета привязаны через SO_BINDTODEVICE к своему netif и через bind()
к своему локальному IP. Ethernet отправляет только на Ethernet IP другой платы,
Wi-Fi только на Wi-Fi IP. Это важно при общей подсети: нельзя засчитать UDP,
который ушёл через default route по другому интерфейсу, как успешную проверку.

Сокеты закрываются при потере IP/линка, создаются повторно после восстановления
и перепривязываются при изменении адреса. Ошибки сокетов повторяются с задержкой,
не перезагружают плату. Для выбора транспорта учитываются application ACK,
а не только успешный sendto() или наличие линка кабеля.

## Протокол и счётчики

Общий пакет 20 байт: magic, version, boot session, sequence, sender,
transport type, kind DATA/PROBE/ACK, acknowledged session.
Формат Wi-Fi/ESP-NOW не изменён; Ethernet использует уже предусмотренный тип.
UDP принимает только заданный IP/порт peer, ESP-NOW только заданный MAC.

Каждая плата отправляет DATA на активном транспорте примерно раз в секунду.
Оба IP-транспорта проверяются независимо: неактивный интерфейс получает PROBE
раз в секунду. В частности, Wi-Fi остаётся проверенным резервом под Ethernet.
Получатель отвечает ACK через тот интерфейс, где пришёл пакет, независимо от
своего активного транспорта. ACK не подтверждается другим ACK.

TX увеличивается только после корректного ACK в пределах таймаута.
RX увеличивается для нового DATA; повторы и старые sequence текущей peer session
подтверждаются, но повторно не учитываются. PROBE и ACK счётчики не увеличивают.
TX/RX общие для всех трёх транспортов, переключение их не сбрасывает.
При потере ACK RX может опережать TX другой платы. Это периодическая передача
тестовых DATA, без повторной отправки потерянных данных приложения.

Callbacks только ставят копии пакетов в очередь. Задача transport обрабатывает
счётчики, ACK и здоровье каналов, публикует потокобезопасный snapshot и обновляет
TFT каждые 250 мс. Callback Wi-Fi/Ethernet/ESP-NOW не обращается к TFT.

## State machine

Таблица приоритетов: ETHERNET, WI-FI, ESP-NOW.

1. DATA продолжает идти по текущему активному каналу, пока он рабочий.
   PROBE кандидата выполняется параллельно, без выключения рабочего драйвера.
2. Для перехода на более приоритетный канал нужны 4 последовательных корректных
   end-to-end ACK. Каждый ACK проверяется по transport, session, sequence и deadline.
   Порог LINK_RECOVER_COUNT можно менять в пределах 3-5.
3. Любая ошибка/таймаут кандидата сбрасывает только его серию успешных ACK.
   Даже ранее подтверждённый резерв после неудачной проверки не может повыситься,
   пока снова не накопит полную серию. Состояние активного канала не меняется.
4. Переход вниз разрешён только при потере физической/IP готовности самого
   активного канала либо после 3 его последовательных ошибок отправки/ACK timeout.
   Одиночная ошибка активного канала ещё не переключает маршрут.
5. При отказе активного выбирается проверенный нижестоящий резерв. Все драйверы
   продолжают работу; Wi-Fi резерв проверяется и при активном Ethernet.

Таймаут ACK 800 мс, интервал DATA/PROBE 1000 мс, отказ после 3 неудач,
повышение после 4 успешных ACK подряд. Истечение старого состояния по времени
применяется только к неактивным резервам. Здоровье активного канала определяется
его собственным обменом, независимо от результата проверок кандидатов.
Если ни один транспорт не подтверждён, выбран ESP-NOW как попытка резервной
связи. На рабочем TFT тогда крупно показано красное NO LINK без подписи маршрута.
При подтверждённой связи название транспорта показывается синим.
Остановившиеся счётчики сохраняют последние значения.
transport_get_status().peer_reachable сообщает подтверждённую доступность и теперь
используется рабочим экраном, чтобы выбранный маршрут не выдавался за рабочую связь.

Ошибка инициализации W5500 логируется, беспроводные транспорты продолжают запуск.
Фатальные ошибки общей инфраструктуры/ресурсов логируются; NVS не стирается автоматически.

## Радио

Рабочая логика Wi-Fi/ESP-NOW сохранена. ESP-NOW peer.channel = 0 использует
текущий Wi-Fi канал при подключении к AP. В отключённом состоянии обе платы
переходят на общий LINK_FALLBACK_CHANNEL, по умолчанию 6.
Переподключение к AP ограничено окнами 4 секунды, между неудачными попытками
20 секунд работы резерва. Поиск AP и разные текущие каналы двух плат могут
временно прерывать ESP-NOW. Ethernet работает на отдельном SPI и не использует радио.
CONFIG_ESP_WIFI_STA_DISCONNECTED_PM_ENABLE отключён; WIFI_PS_NONE сохранён.

## Диагностика

LINK_DIAGNOSTICS = 1 включает RX/ACK-логи и DIAG каждые 5 секунд.
DIAG содержит wifi_ip и eth_ip, активный транспорт, общие TX/RX, MAC delivery
ESP-NOW и queue_drops. После проверки можно поставить LINK_DIAGNOSTICS = 0.
Ошибки UDP содержат destination/errno. Отклонённые пакеты показывают причину.

## Сборка и прошивка пользователем

Ассистент сборку и прошивку не запускает. Ethernet-этап пока проверен по
исходникам и API установленного ESP-IDF 5.4.4; компиляция и работа W5500
на двух платах ещё требуют проверки пользователем. Wi-Fi/ESP-NOW до этого
этапа были подтверждены пользователем.

```sh
cd esp32-s3-eth-espnow
idf.py build
idf.py -p /dev/cu.usbmodem101 flash monitor
```

На вторую плату прошивается тот же build через её фактический serial port.
Включение драйвера W5500 сделано в sdkconfig, дополнительных пакетов не требуется.

## Проверка на двух платах

1. Прошить обе платы новой версией, подключить Ethernet к роутеру/свитчу.
   Проверить Cable link UP, Ethernet IP .110/.111 и UDP bound to свой netif.
   После четырёх ACK обе платы должны показывать ETHERNET, TX/RX увеличиваются.
2. Отключить кабель одной платы. Обе должны перейти на WI-FI: отключённая
   по link DOWN, другая по ACK timeout, даже если её собственный кабель подключён.
3. Подключить кабель обратно: автоматически вернуться на ETHERNET после ACK.
4. При отключённом Ethernet выключить Wi-Fi роутер: перейти на ESP-NOW.
   Включить роутер: вернуться на WI-FI, затем после подключения кабеля на ETHERNET.
5. Перекрыть UDP по кабелю при сохранённом линке: проверить отказ по ACK timeout.
6. При Ethernet активном выключить только Wi-Fi: ETHERNET должен продолжить работу.
7. Проверить холодный старт без кабеля, восстановление Ethernet и перезапуск одной
   платы: оставшаяся плата не сбрасывает счётчики и принимает новую boot session.

## Стартовая заставка TFT

Сразу после инициализации TFT показывается CONNECTING и три анимированные точки.
После определения MAC сверху появляется A/B. До запуска сетевой задачи показана
статичная первая фаза, затем точки анимируются каждые 500 мс.

Начальные переключения транспорта скрыты заставкой. Минимальное время заставки
4 секунды от запуска задачи transport. Выбранный транспорт должен быть подтверждён
application ACK и оставаться тем же без ошибок обмена ещё 3 секунды. Изменение
транспорта или обнаруженная ошибка сбрасывают интервал стабилизации.
После выполнения условий появляются транспорт и накопленные TX/RX.

Если условия не выполнены за 20 секунд, надпись меняется на WAITING / PEER;
заставка не объявляет связь успешной по одному лишь таймеру. При позднем запуске
второй платы рабочий экран появится автоматически после стабилизации обмена.
После первого успешного выхода заставка больше не включается: runtime failover
сразу отображается прежним рабочим экраном.

Настройки в link_config.h: LINK_STARTUP_MIN_MS, LINK_STARTUP_STABLE_MS,
LINK_STARTUP_WAIT_NOTICE_MS. DATA/PROBE/ACK и реальные TX/RX продолжают работать
под заставкой; блокирующих задержек для сети не добавлено. Отрисовка происходит
из app_main при инициализации и из обычной transport task, не из callbacks.

Проверка пользователем: одновременно включить обе платы; убедиться, что начальные
смены маршрута не видны под CONNECTING, затем появляется подтверждённый канал.
Включить вторую плату с задержкой более 20 секунд: первая остаётся на WAITING PEER,
после появления связи выходит на рабочий экран. Затем проверить отключение кабеля
и Wi-Fi: runtime переключения и непрерывность счётчиков должны остаться прежними.
Сборку/прошивку этого изменения ассистент не запускал.

## Проверка удержания рабочего канала

При активном Wi-Fi подключить Ethernet, но заблокировать UDP между Ethernet IP:
Wi-Fi DATA и общие TX/RX должны продолжиться, без перехода на ESP-NOW. Затем
разблокировать UDP: переход на ETHERNET только после streak=4/4. Прервать проверку
после 1-3 ACK: серия Ethernet сбрасывается, Wi-Fi остаётся активным. Аналогично
проверяется восстановление Wi-Fi при активном ESP-NOW. Физическая потеря рабочего
кабеля/IP и три ошибки его DATA обмена по-прежнему вызывают failover.

Один радиомодуль ESP32-S3 остаётся аппаратным ограничением: попытка STA найти AP
может временно прервать ESP-NOW, хотя state machine не выключает его драйвер.
Логическое удержание рабочего транспорта не обеспечивает одновременную работу
ESP-NOW на резервном канале и поиск Wi-Fi на других каналах без пауз.
Сборку и прошивку этого изменения ассистент не запускал.

## Отключение второй платы

Если вторую плату выключить, DATA не поступает и application ACK не приходит:
TX/RX должны остановиться. TX не является счётчиком попыток отправки.
После обнаружения отказа по правилам ACK/готовности интерфейса рабочий экран
показывает красное NO LINK без названия транспорта ниже.
Если это происходит ещё во время первой заставки, остаётся CONNECTING/WAITING PEER.

Повторные DATA/PROBE продолжаются без участия пользователя. После включения второй
платы и восстановления подтверждённого канала NO LINK автоматически заменяется
на ETHERNET, WI-FI или ESP-NOW; сохранённые счётчики продолжают увеличиваться.
Перезагружать оставшуюся плату не требуется. NO LINK показывает отсутствие
подтверждённого обмена и не определяет причину (выключена плата, нет сети и т.п.).
Сборку и прошивку изменения TFT ассистент не запускал.

## Порядок байтов цветов статуса

Framebuffer uint16_t на ESP32-S3 хранит младший байт первым, а существующий
ST7789 принимает RGB565 старшим байтом первым. Драйвер передаёт буфер напрямую.
Поэтому COLOR_RED для NO LINK хранится как 0x00F8 (SPI F8 00), COLOR_BLUE для
названий транспортов как 0x1F00 (SPI 00 1F). Изменена только упаковка этих двух
цветов; порядок каналов и инициализация панели сохранены.
Порядок байтов проверен локально, цвета на аппаратном дисплее после этой правки
ещё не проверены. Сборку и прошивку ассистент не запускал.

## Стрелки активности TX/RX

Справа от TX показана стрелка вправо, справа от RX стрелка влево. При увеличении
соответствующего счётчика стрелка подсвечивается цветом своей надписи и смещается
в направлении передачи/приёма в течение 750 мс, затем возвращается в тёмно-серое
состояние. RX и его активная стрелка жёлто-оранжевые; активная стрелка TX использует
тот же существующий салатовый оттенок, что и надпись TX.
TX срабатывает по подтверждённому DATA ACK, RX по новому DATA. PROBE, служебные
ACK и неудачные попытки отправки стрелки не включают.

Анимация обновляется в существующем display_update из задачи transport каждые
250 мс, без delay и без отрисовки в callbacks. Под заставкой отдельные стрелки
не показываются. При первом появлении рабочего экрана накопленные ранее
счётчики служат исходным состоянием и не запускают ложную анимацию.
Для длинных счётчиков шрифт автоматически уменьшается с 3 до 2, чтобы стрелка
и число помещались в 240 пикселей. Пины, инициализация TFT, сетевой протокол
и state machine транспорта не изменены. Сборку/прошивку ассистент не запускал.
